# AirCast · turn Windows into an AirPlay receiver

[中文](README.md) | **English**

[![build](https://github.com/oskarwu2022/aircast-windows/actions/workflows/build.yml/badge.svg)](https://github.com/oskarwu2022/aircast-windows/actions/workflows/build.yml)
[![release](https://img.shields.io/github/v/release/oskarwu2022/aircast-windows?label=release)](https://github.com/oskarwu2022/aircast-windows/releases/latest)
[![license](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

A zero-setup AirPlay mirroring receiver for Windows: **open Control Center on your iPhone / iPad / Mac,
tap Screen Mirroring, pick your PC** — screen and audio show up on the Windows desktop.
Everything stays on your local network; no cloud, no account, no internet required.

The GUI shell is the Python code in this repo (MIT). The AirPlay protocol core is
[UxPlay](https://github.com/FDH2/UxPlay), compiled from source by the scripts in this repo and shipped
as a portable folder — no Python, Bonjour, or GStreamer install needed.

```
iPhone ──AirPlay(LAN)──> AirCast.exe (GUI) ──> uxplay.exe ──> GStreamer ──> screen / audio
```

## Features

- 🖥️ **Portable**: grab the zip from Releases, unzip, double-click `AirCast.exe`. Nothing else to install
- 🔊 **Video + audio**: hardware H.264 decode via D3D12, audio through WASAPI
- 🀄 **Non-ASCII device names**: works around the Windows ANSI-argv problem (options are passed via a UTF-8 `UXPLAYRC` file)
- 🎛️ **Everything in one window**: device name, 720p–4K, fullscreen, mute, one-time PIN, allow takeover, low-latency mode, record to mp4, live log, connection state
- 📱 **QR onboarding**: the QR code opens a small local page with connection steps — handy for classrooms and meeting rooms
- 🛡️ **One-click firewall**: elevated script opens the required ports and switches the network profile to Private
- 🧰 **Built-in self test**: `AirCast.exe --selftest` writes environment + startup diagnostics to `data\selftest.log`

## Quick start

1. Download `AirCast-Windows-x64.zip` from [Releases](../../releases/latest) and unzip anywhere
   (`AirCast.exe`, `_internal\` and `runtime\` must stay side by side)
2. Double-click `AirCast.exe`, then click **▶ 启动接收端** (Start receiver)
3. iPhone: Control Center → **Screen Mirroring** → pick your device name
4. Stop: click **■ 停止** in the app, or "Stop Mirroring" on the phone

To start the receiver immediately on launch, use `AirCast.exe --autostart`.

> Phone and PC must be on the same LAN. Wired PC + Wi-Fi phone on the same router is fine.

## Options

| Option | UxPlay flag | Notes |
|---|---|---|
| Device name | `-n` | What the phone shows; UTF-8 / emoji supported |
| Quality | `-s WxH@fps` | 720p30 / 1080p30 / 1080p60 / 2K30 / 4K30 — a request, the phone decides |
| Fullscreen | `-fs` | Also toggled with `Alt+Enter` inside the video window |
| Audio | `-a` (when off) | Video only |
| Require PIN | `-pin` | One-time PIN shown in the app for each connection |
| Allow takeover | `-nohold` | Default is exclusive ownership by the current client |
| Low latency | `-vsync no` | Trades AV sync for lower latency |
| Record to mp4 | `-mp4` | Saved as `data\record-*.mp4` |

Fixed ports (`-p`): TCP 7000/7001/7100, UDP 6000/6001/7011; discovery uses UDP 5353 (mDNS).

## Build from source

Requirements: **Windows 10/11 x64**, [MSYS2](https://www.msys2.org/) (default `C:\msys64`), Python 3.10+.

```powershell
git clone https://github.com/oskarwu2022/aircast-windows.git
cd aircast-windows
```

**① Install MSYS2 dependencies** (open the "MSYS2 UCRT64" terminal):

```bash
pacman -S --needed git \
  mingw-w64-ucrt-x86_64-{cmake,gcc,ninja,pkgconf,libplist,openssl} \
  mingw-w64-ucrt-x86_64-{gstreamer,gst-plugins-base,gst-libav,gst-plugins-good,gst-plugins-bad}
```

**② Build UxPlay and collect the portable runtime** (same UCRT64 terminal, repo root):

```bash
bash build/build-uxplay.sh     # clones + builds UxPlay 1.74 -> .work/UxPlay/build/uxplay.exe
bash build/make-runtime.sh     # exe + DLL closure + GStreamer plugins -> runtime/
```

**③ Package the GUI** (regular PowerShell, repo root):

```powershell
powershell -ExecutionPolicy Bypass -File build\build-exe.ps1
# output: dist\AirCast\  (runnable)  and  AirCast-Windows-x64.zip
```

**④ Self test**

```powershell
Start-Process .\dist\AirCast\AirCast.exe -ArgumentList '--selftest' -Wait
Get-Content .\dist\AirCast\data\selftest.log
```

Run the GUI straight from source (no packaging):

```powershell
python app\aircast.py
```

CI (`.github/workflows/build.yml`) does all of the above on `windows-latest` and publishes a Release
whenever a `v*` tag is pushed.

## Layout

```
AirCast.exe            main program (PyInstaller onedir; keep _internal\ and runtime\ beside it)
_internal\             ← generated by packaging
runtime\               ← generated by build: uxplay.exe + full GStreamer stack (~230 MB)
app\
  aircast.py           all GUI + process-management logic (~740 lines, single file)
  aircast.ico          icon
  vendor\qrcode\       pure-Python QR encoder (BSD)
scripts\
  allow-firewall.ps1   firewall allow-rules (self-elevating)
build\
  build-uxplay.sh      build UxPlay
  make-runtime.sh      assemble portable runtime
  build-exe.ps1        package + assemble + zip
.github\workflows\build.yml   CI: build, smoke test, release
```

Runtime data lives in `data\`: `uxplayrc.txt` (the actual options passed to UxPlay),
`gst-registry.bin` (plugin cache), `record-*.mp4`, plus `aircast-settings.json` for UI settings.

## Troubleshooting

**Device not listed on the phone**

1. Click **配置防火墙** in the app, or run `powershell -ExecutionPolicy Bypass -File scripts\allow-firewall.ps1`
2. The network profile must be **Private** (Settings → Network & Internet → Wi-Fi → properties)
3. Disable **AP / client isolation** on the router; no VPN on the phone; don't use a guest SSID
4. `AirCast.exe --selftest`, then read `data\selftest.log` after ~8 s (ends with `SELFTEST OK`)
5. Verify the advertisement from any machine with Python:
   ```powershell
   python -c "from zeroconf import Zeroconf,ServiceBrowser; import time; z=Zeroconf(); ServiceBrowser(z,'_airplay._tcp.local.'); time.sleep(5); z.close()"
   ```

**Listed but black screen / stuttering**

- Change the video sink in `data\uxplayrc.txt`: `vs "d3d12videosink"` → `vs "d3d11videosink"`
- Drop to 1080p30, or enable "low latency"
- Make sure the GPU driver is healthy (D3D12 hardware decode depends on it); disable hybrid/eco GPU switching
- The log pane shows GStreamer warnings — copy them into an issue

**"uxplay.exe not found"**

Incomplete unzip: `runtime\uxplay.exe` must exist next to `AirCast.exe`.

## Known limitations

- **DRM content**: FairPlay-protected Apple TV App video cannot be mirrored (audio only) — true for every open-source receiver
- **No AirPlay 2 multi-room audio**; audio-only mode (Apple Music) works
- **HLS streams** (e.g. YouTube app video) are disabled (UxPlay's `-hls` is not enabled here)
- **macOS clients** can mirror, but Apple's built-in "AirPlay to Mac" is better
- Sleep/suspend on the PC interrupts the session — disable sleep for long presentations

## Implementation notes

- **Discovery**: UxPlay 1.74 ships an internal mDNS responder and advertises `_airplay._tcp` / `_raop._tcp`
  (declaring `model=AppleTV3,2`), so Bonjour is not required on Windows. Verified to coexist with the
  system mDNSResponder service.
- **Non-ASCII device names**: the Windows CRT converts argv using the ANSI code page, so UTF-8 names arrive
  mangled and UxPlay rejects them. We write the options into a UTF-8 startup file and pass it via the
  `UXPLAYRC` environment variable (see `write_rc()`).
- **Log decoding**: on Chinese Windows, `netstat` and GStreamer emit GBK while Python 3.11+ decodes UTF-8 by
  default, raising `UnicodeDecodeError`. Child output is read as bytes and decoded per line with a
  utf-8 → gbk fallback (`smart_decode()`).
- **Connection state**: poll `netstat` every 2 s for an ESTABLISHED connection on port 7000, combined with
  log keywords, to switch between "waiting" and "mirroring".
